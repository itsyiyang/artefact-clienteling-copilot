# 三方案对比实验协议 v0.1

2026-11-09｜草案，未执行。正式生成与Judge不得使用同一模型；现有Qwen自评结果仅属原型调试证据，不作为独立质量验证。

## 模型与评审分工

- 生成：继续本地Qwen3:8b，包括理解、规划与改写。
- 运行时Judge：另选不同模型家族，具体型号待小样比较，不因不同模型就假定可靠。Gemma3:4b仅为可本地试验的候选，未选定、未下载、未验证中文客户沟通评审能力。
- 人工：用户提供逐项判断、证据、理由和修改建议，建立校准标签；业务同事可复核分歧。模型意见与人的意见冲突时记录并讨论，不能机械投票。
- 确定性检查：结构、候选数、证据引用定位、运行/版本完整性；不能替代语义判断。
- 不使用生成模型做正式Judge，不自动fallback回Qwen；独立Judge未就绪则标记待配置，先走人工基准。现有Demo尚未修改，仍使用Qwen自评，不能将它描述成已切换。
- 保持零云端推理预算。借鉴公开方法不等于调用其模型；不自动配置任何云端grader或使用已有API密钥/登录额度。

## 方案控制

| 组 | 流程 | 目的 |
|---|---|---|
| A | 相同原始输入和品牌规则 → 直接生成三候选 | 基线 |
| B | 相同输入/规则 → 独立理解与规划 → 按三个方向生成 | 衡量显式策略价值 |
| C | 使用B同一次原始输出 → 独立Judge → 最多两轮定向修正、整组复评 | 隔离检查+修正的增量效果 |

A/B不使用测试标签或修订反馈。C只接收运行时Judge建议，不接收留出人工答案。全部结果由同一独立评估规则检查；对A/B的事后评分不可反向改变其输出。主要结论以人工盲评为准，自动Judge只作辅助及运营指标。C使用运行时Judge自判的改善必须与人工改善分开报告。

冻结生成模型/量化、温度、上下文长度、规则、提示、案例、评分表、重试预算和硬件。A与B提供相同信息，A不强制输出理解/策略；B增加调用次数与token成本是方法代价，必须报告，不声称纯提示因果实验。顺序交错或随机并记录，避免模型冷热和系统负载偏差。

## 执行顺序

1. 先人工评审12例校准集中的六场景示例和已知失败，形成参考标签（12+38划分待批准）。先覆盖短历史、长历史、偏好更新与不同拒绝范围。
2. 用已标注小样测试独立Judge候选：硬约束漏判、误报、证据定位、中文理由是否准确、耗时；人工选择是否可用。只在校准集调整评分说明。
3. 冻结数据与方法，在38例留出运行A/B/C。50例均保留记录，但校准12例与留出38例分开汇报，不能把调参案例当未见测试。
4. 人工对留出A/B/C的最终三候选整组盲评，隐藏方案名、模型名和Judge分数，随机展示顺序。记录单条和整组，不把150条消息视作150个独立客户样本。建议所有留出组均人工评；如果只抽查，提前固定抽样方式并只报告抽样结论。
5. 同一case的A/B/C做配对比较，报告改善、退化、不变及并列，而非只给总体平均分。可在校准集中挑6例额外重复运行2次观察波动，不把额外运行算新增客户。
6. 保存所有失败和重试，不筛选最佳一次充当首次结果。人工发现的新留出缺陷归档，修复后另标版本，不悄悄重算原实验。

## 指标与分母

正常三候选测试设N为固定分区中所有计划运行的案例数，技术错误也计入N。Judge口径与人工口径各报告一套，不能混用。

- 首次通过率 = 首次整组同时通过底线、价值、质量的案例数 / N。
- 修订后累计通过率 = 首次通过数 + 预算内修订后通过数，再除以N。
- 修订挽救率 = 初次未通过但修订后通过数 / 初次未通过数；分母为0时记N/A。
- 耗尽失败率 = 完成允许修订次数后仍不通过数 / N。另列技术失败/超时/未执行/中止比例，不能把这些混作已耗尽。
- 最终未通过率 = 所有最终未成功案例数 / N；与累计通过率互补。报告失败例外展示数量，其不算通过。
- 单条底线失败率、价值不足率、整组差异失败率；客户历史约束召回=正确提取的应生效约束/参考应生效约束，误提取另外计数。
- Judge漏判率 = 人工判失败而Judge判通过数 / 人工判失败数；误报率 = 人工判通过而Judge判失败数 / 人工判通过数。verify单列，展示混淆表和实际分子/分母。
- 耗时：各阶段、首次生成、修订及端到端（包含Judge与模型切换）分别记录；按方案给中位数、P90和范围，另列冷启动/热运行。长历史、重试次数分层观察。云端费用为0不意味着计算免费。

题目要求的50例×3中文输出与三方案实验记录分别盘点。另设不适合触达压力集，不把正确阻断记成三输出成功。12校准/38留出和额外压力集的数量是草案，需冻结后才能执行。
