# 六案例校准闭环

2026-11-09｜阶段1已准备，等待用户审核；没有新的模型运行或评测结论。

## 文件

- review-pack.md：用户可读的完整资料与待审参考话术。
- inputs.json：仅生成输入，无正确答案或评分字段。
- review-key.json：审核用成功/失败条件、参考方向、待讨论问题，不提供给生成器。
- human-review.csv：空白人工记录表；可直接在聊天反馈，不必填表。

所有案例与参考组由AI助手拟写，不冒称用户标注、人工独立样本或Qwen运行结果。校准组含六场景，v0.2历史条数依次9、13、4、5、3、2。这是小样覆盖，不代表50例最终配额。

## 闭环与交付门

1. 用户审核输入是否合理、成功条件是否公平、参考策略是否真的不同。状态：pending。优先处理P01生日、P03售后、P05邀请的整组差异边界；不能把未认可的参考组当金标准。
2. 根据用户意见修订案例/评分并记录版本，批准后冻结pilot输入。若单例获批，可先运行该例，不把整组默认批准。
3. 运行Qwen生成，保存原始候选、理解/策略（若已实现）、实际模型/提示/规则/数据版本及耗时。禁止把参考输出填入结果代替模型生成。现有Demo的理解/规划合并实现若被使用，必须标为prototype，不能冒充独立规划实验。
4. 用户先评模型输出，不先显示Judge分数；取得人工记录后再展示Qwen独立Judge调用及双方分歧。评分规则与案例事实可给Judge；隐藏预期参考文案和人的评分以免影响首轮分歧测量。
5. 区分输入歧义、生成失败、评分误判；依照证据修订评分或工作流。是否换Judge模型由同一批人工已评输出上的表现决定；无自动下载或切换。
6. 再次运行时保留v1，不覆盖失败；已用于修改的六例属于校准/回归资料，不能再当留出集。冻结方法后扩展50例及独立留出评测。

## 运行记录要求

case_id, trial_id, dataset_version, pipeline_version, generator_model, judge_model, prompt_versions, raw_output, structured_plan_if_available, validation_errors, human_labels, judge_labels, disagreements, revision_parent, retry_count, stage_latency_ms, final_status。

统计首次整组通过率、预算内修订后累计通过率、修订挽救率、耗尽失败率；技术错误/超时独立列出，端到端耗时包含Judge及重试。原型手动修订与未来自动修订分别标注。用户未审核或模型未运行时指标为not_run，不能填0%或虚构成绩。
