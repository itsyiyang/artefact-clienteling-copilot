# 客户模拟 Agent：实现与使用

2026-11-09。它是离线测试数据构建工具，不是客户回复机器人，也不是Judge。使用结构化JSON Schema约束的两个本地Qwen3:8b调用依次创建档案、基于冻结档案创建场景/产品/历史/评审依据。参考CA输出不由它生成。

运行：保持Ollama开启，在项目目录执行 `npm run simulate:customer`。默认只创建一个新产品推荐样本，不覆盖P01–P06。修改evaluations/pilot-v1/customer-agent-config.json可指定场景、主动/回复、资料完整度、历史条数、品类和测试目的；自定义配置可用 `node scripts/customer-agent.mjs <配置路径>`。

## 输出与隔离

每次在work/customer-agent/<唯一ID>/保存配置和状态manifest.json、profile.json、两次原始模型输出trace.json、生成输入input.json及单独review-key.json。状态pending_user_review仅代表结构检查通过，不代表业务正确。失败保存状态和已取得输出，不静默重试或伪造成功；需要用户修订后再开新运行。

## 可计算字段

年龄由完整生日与案例日期计算；属相使用Node内置Intl农历，按农历新年而非1月1日或立春划分。生日之前与之后年龄、农历年界两侧、非法日期均有测试。生肖不用于推断性格、财富或品味。职业、兴趣等允许缺失；购物历史分别表达已购、确认无购买、无系统记录。

## 验证范围

当前代码检查必填结构、年龄、日期、交易记录与状态、聊天长度/时间顺序、编号唯一性、评审引用存在性。语义一致性（聊天是否吻合全部档案、SKU组合是否合理、CA是否专业）仍须人工审核；不得把引用存在等同引用支持判断。长历史最多30条，当前上下文8192，超长或输出截断可能失败，不会无声裁剪；实际吞吐与语义质量需要继续测试。

网页原有“生成虚构输入草案”仍是旧版简单调用，本次未替换它。正式生成—规划—Judge工作流也未在本次改造。完整50例暂不运行。

可选复用已生成档案：`node scripts/customer-agent.mjs <配置路径> <profile.json路径>`；复用会再次验证档案，并在manifest中记录来源。原始模型输出保留，字符串null仅做有记录的空值规范化，不编造职业。
