# 50例本地生成 v0.2

本轮依据 `clienteling_messaging_reference.md` 和用户六例人工反馈调整生成提示。参考文档是表达参考，不是商品或活动事实来源。

## 采用与冲突处理

- 采用自然、温暖、克制的微信表达，建议60–140字，一个主要目的和最多一个下一步。
- 品牌理念采用新参考的“留白之间，天地为序”。
- 用户反馈优先：禁用“不用/不必特意回复”；生日不硬塞包装、丝巾系法等不相关细节；重联必须有真实新增具体价值，不能仅靠久未联系。
- 名字优先使用历史确认的姓氏＋女士/先生；无可靠称谓时用“您好”，不猜性别。
- 常规CA护理咨询、反馈、维修联系、预约协助默认允许，不要求逐项权限证明；不承诺服务结果、费用或工期。
- 保留题目要求的三条候选，而非参考文档的主话术、短版和回复分支。三个候选须有实质不同的信息重点或帮助方式。
- 完整历史与事实输入保留。请求中仅移除重复的商品 `claim_evidence` 溯源字段；源文件完整快照仍保存。

## 本地运行与查看

在仓库根目录、Ollama运行且已安装 `qwen3:8b` 的情况下：

```sh
node scripts/run-fifty.mjs
```

默认目录 `evaluations/runs/fifty-generation-v0.2/`。同一命令会跳过已成功生成的案例，不重复覆盖输出。若要开始全新的实验，指定新目录：

```sh
node scripts/run-fifty.mjs evaluations/runs/my-new-run
```

新实验从 `evaluations/test-set-50-v1/inputs.json` 和 `prompts/generation-v0.2.md` 冻结快照；之后修改这两份源文件不影响正在运行的实验。

- `test-results-50.csv`：用户指定八列，三条正文来自实际Qwen返回，每例完成立即更新。
- `run-status.csv`：每例状态、累计耗时、调用次数及原始结果文件。
- `TCxxx.attempt-n.json`：原始Ollama响应、解析结果、耗时、失败信息。
- `TCxxx.attempt-n.request.json`：完整实际请求及模型参数。
- `manifest.json`：模型摘要、代码commit、提示/输入/参考文档哈希和运行进度。
- `generation-prompt.md`、`inputs.json`、`reference-snapshot.md`、`runner-snapshot.mjs`：实验快照。

只调用127.0.0.1的Ollama，没有云端推理调用。此命令不运行Judge。单调用内部规划＋生成仍是原型，不宣称已实现独立Planner。最多两次技术重试，不是质量修订；未通过结构校验时保留原始返回且CSV留空。成功状态只代表恰好三条非空候选，不代表符合所有业务规则。

## 评估边界

50例是21个来源案例＋29个显式合成分支；同一客户和对话的分支相关，不是50个独立客户。重新激活集中在C04，仅一个主动联系案例，覆盖弱点保留。旧六例与旧CSV留存，不把新输出写回历史基线。下一步由业务review，再校准Judge并运行对照；本轮没有生成质量通过率。
